## Context

见 `proposal.md` 的问题说明。普通分镜图的唯一渲染出口是 `render_storyboard_image_prompt`：预览、入队校验和正式执行都经此函数。参考图由 `collect_storyboard_references` 装配，mention 经通用编号器把 `@[名称]` 换成「图N」。项目 `characters` 的描述和分镜引用字段中的角色名单不进入该提示词，也不进入 `artifact-visual/storyboard-image` 视觉依据（当前 `kind_version=1`）。

宫格已在 `lib/grid/character_identity.py` 实现同一套确定性身份投影，并在提示词里写「【角色身份】」与逐格清单。宫格专用 mention 渲染把角色写成「角色名（图N）」。本变更把这四层约束接到普通分镜，并抽出共享投影，避免两套描述来源。

入队校验 `_build_prompt` 目前不带参考图，只确认 `image_prompt` 可渲染；正式提示词仍在执行时按裁剪后的参考图重建。图片编辑路径用编辑指令重建分镜图依据，不走角色身份约束。

`CONTEXT.md` 目前把分镜 `@[名称]` 一律解释成换成「图N」；角色 mention 语义变化后须改释义。

## Goals / Non-Goals

**Goals:**

- 普通分镜图提示词与宫格使用同一份角色描述/名单投影，避免两套外貌来源。
- 预览、入队校验、正式执行和产物规划器读取同一角色语义；图N只按当次实发参考图绑定。
- 修改角色描述或该分镜角色名单会使相关普通分镜图变旧。

**Non-Goals:**

- 不改变参考图选择、装配序或 `max_reference_images` 去尾裁剪。
- 不改写剧本里的 `image_prompt`，不从自然语言抽取站位。
- 不改宫格对外提示词与视觉依据行为（共享抽取后宫格输出须保持既有字符串与依据字段）。
- 不把身份约束接到图片编辑、参考生视频或视频提示词。
- 不承诺模型绝不违约，不成图识别，不自动重试。

## Decisions

### 1. 抽出共享角色身份投影

把 `lib/grid/character_identity.py` 升为 `lib/storyboard_character_identity.py`（名称、描述、逐条名单、普通/衍生描述拼接、缺失降级）。宫格构建器改为导入共享模块；投影算法与排序规则不变。

普通分镜对单条分镜调用同一投影，取 `identities` 与唯一一条 roster。备选方案是普通分镜直接依赖 `lib.grid` 或复制一份投影。前者让分镜渲染依赖宫格包，后者会让衍生描述规则分叉，因此不采用。

### 2. 普通分镜渲染出口接收身份上下文

`render_storyboard_image_prompt` 增加可选 `character_context`。有角色时在 `Style` / `Reference_Images` 之后、`Scene` 之前插入：

- 一次性 `【角色身份】`（名称、可选图N、项目描述、禁止互换句）
- `本镜角色：…` 清单（单人「只出现上述角色1人」；多人「各恰好1人」且不得复制/融合/替换/互换）

无角色时两段都不输出。清单用「本镜」而不是宫格的「本格」，避免把单张分镜说成画格。身份段与禁止换脸句与宫格共用同一渲染函数，仅单位名词不同。

`Reference_Images` 行保持现有按类型分组（含商品保真句），不改为逐图具名。名称绑定放在身份表和 mention 里，避免和商品分组声明抢同一行。

备选方案是把宫格的 `include_logical_ids=True` 声明也搬过来。它与身份表重复，且会改动现有声明行测试与商品保真句排版，因此不采用。

### 3. 角色 mention 保留名称

角色 mention 渲染为「角色名（图N）」；无实发槽位时退化为角色名。判定「这是角色」以身份投影的名单加上参考图 `logical_type == character` 为准，这样引用字段漏写但参考图里已有角色时，正文仍不会丢掉名字。场景、道具、商品继续「图N」。

入队校验仍可不传参考图：此时身份表带名称和描述、不带图N，mention 为角色名。正式执行和预览在裁剪后传入同一 `character_context` 与实发参考图，图N 才出现。

### 4. 视觉依据升级并纳入角色语义

`artifact-visual/storyboard-image` 升到 `kind_version=2`，inputs 增加该分镜规范化角色名单及对应描述（与宫格 cell `characters` 同形：`[{name, description}]`）。图N 仍不进依据。因此：

- 改角色描述或该分镜引用名单 → 分镜图变旧
- 只改 `video_prompt` → 分镜图依据不变

执行器、产物补录规划器、预览必须调用同一投影。图片编辑继续用编辑指令重建依据，可省略身份上下文（空名单）；编辑本来就不是按角色表生成。

kind version 升级会让存量普通分镜图被识别为需重新生成，这是目标定义变化的预期结果，不做项目数据迁移。

### 5. 调用方传入剧本角色字段与项目角色表

正式执行 `execute_storyboard_task`、预览 `preview_item_prompts`、入队校验 `_build_prompt`、规划器 `_plan_storyboards` 在已有 `get_storyboard_items` 返回值上把 `char_field` 与 `project["characters"]` 交给投影。`image_prompt` 原文仍存任务 payload，执行时实时渲染，不信任队列里可能过期的包装文本。

## Risks / Trade-offs

- [完整角色描述拉长普通分镜 prompt] → 身份表只写一次，清单只写名称、编号和人数。
- [角色描述含「需补充」等非视觉文本] → 忠实使用项目数据，不做启发式摘要。
- [引用名单与画面正文不一致] → 名单是身份与数量真相，正文是构图真相；现有 mention 警告继续负责未绑定引用。
- [模型仍可能忽略约束] → 正向清单加参考绑定降低概率；检测与重试不在范围。
- [kind version 升级使存量分镜图显示过期] → 文件仍可读，用户显式重生后才带新约束。
- [共享抽取误改宫格字符串] → 宫格既有单元测试作为冻结；抽取后宫格输出必须保持不变。

## Migration Plan

1. 部署新提示词与视觉依据逻辑，不迁移项目 JSON 或分镜图文件。
2. 现有普通分镜图继续可查看；新鲜度按新目标依据标记为需重新生成。
3. 新建或重新生成的普通分镜图写入带身份约束的正式提示词。
4. 回滚时恢复旧渲染与 `kind_version=1`；已按新依据登记的产物在旧目标下可能被判过期。
